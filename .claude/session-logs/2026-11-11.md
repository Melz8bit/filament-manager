## Work Done

### Inventory: Mark Empty

User wanted a way to flag a spool as used up without deleting the record — keeps
purchase history, SKU/label, and cost data (feeds into `cost_estimate`/dashboard
stats) around for reference instead of losing it.

- `SpoolMarkEmptyView` (`POST /inventory/<pk>/mark-empty/`): zeroes `remaining_g`,
  saves, returns the re-rendered `spool_card.html` partial for htmx requests
  (`request.htmx`-aware, same pattern as `SpoolDeleteView`), or redirects back to
  Inventory with a success message for a plain non-JS POST.
- "Mark Empty" button added between Edit and Delete on both card layouts —
  `spool_card.html` (standalone Cards view) and `spool_group_card.html` (grouped
  view's per-spool row) — amber, sitting between Edit's neutral gray and Delete's red.
- Used htmx's built-in `hx-confirm` attribute rather than the heavier swap-based
  confirm flow `SpoolDeleteView` uses — reasonable given Mark Empty is trivially
  reversible (just edit the weight back up), unlike an actual delete.
- Button only renders when `spool.remaining_g > 0` — hidden once a spool is already
  at 0g, so there's nothing to click that wouldn't do anything.
- No remaining_g change-history/audit trail added — the existing Edit form already
  lets any user silently overwrite `remaining_g` with no history tracking, so adding
  special undo/audit machinery just for this one action would have been inconsistent
  with how the rest of the app treats that field.
