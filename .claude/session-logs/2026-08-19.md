### Bug fix: 500 error uploading a specific `.gcode.3mf`

User added `Jackie_Logo_Stamp.gcode.3mf` to the project root and got a server 500 trying
to log it as a print (other `.gcode.3mf` files upload fine).

- Reproduced by running `parse_3mf()` directly against the file — it returned a color of
  `#FFFFFFFF` (8 hex digits — `RRGGBBAA`, includes an alpha channel), unlike every other
  `.3mf` in the project (`uploads/prints/`), which all have plain 6-digit `RRGGBB` colors.
- Traced the actual crash site: `PrintSpool.objects.create(slicer_hex=slot["hex"])` in
  `views.py` bypasses any form validation, and `PrintSpool.slicer_hex` is
  `CharField(max_length=7)`. SQLite wouldn't enforce that, but this project's `DATABASE_URL`
  points at Supabase Postgres even locally — Postgres enforces `varchar(7)` at the column
  level, so the insert raised `StringDataRightTruncation`, uncaught, surfacing as an
  unhandled 500.
- Fix: `parsers.py` — both `parse_3mf` and `parse_gcode` now truncate any parsed hex color
  to 6 digits (`hex_val[:7]` including the `#`) before returning it, dropping the alpha
  channel when present. Verified against the actual failing file: now parses to `#FFFFFF`
  cleanly.

  upload live — confirmed working, then stopped the server.
