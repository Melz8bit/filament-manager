### Per-spool SKU + printable labels

User's problem: multiple physical spools of the same color/material look identical in
the UI (e.g. two spools of SUNLU Red PLA) and they can't tell which one is actually
loaded when logging a print. Wanted: (1) every spool to have its own unique SKU, (2)
the SKU visible in the Log a Print spool-selection list, (3) a way to download/print
that SKU to physically tape onto each spool.

- Investigated the existing SKU/Generate/QR/Scan feature on the Add Spool form first —
  it already existed and was already *intended* to be a per-spool unique code (the
  "Generate" button makes an `FT-XXXXXX` random code, distinct from the shared
  `FilamentProduct.sku`), but had three real gaps: the whole section was gated
  `{% if not form.instance.pk %}` so it never appeared on the **Edit** form (no way to
  add/view an SKU for a spool that already exists); the spool-selection dropdowns never
  showed the SKU; and there was no persisted/downloadable label image, only a
  transient client-side QR canvas with a "screenshot it" instruction.
- Checked real production data before changing anything: 43 spools total, 25 already
  had a unique SKU (some scanned off the manufacturer's own printed barcode, some
  already `FT-`-generated), 18 were blank, zero collisions among the 25.
- Asked the user two targeted questions before touching live data: fill method for the
  18 blanks (bulk-generate now vs. walk through each manually) — chose bulk-generate;
  label medium — has a small Bluetooth label printer paired to their phone (its own
  app, not browser printing), which ruled out a `@media print` sheet-grid approach in
  favor of per-spool downloadable PNGs.
- Bulk-generated unique `FT-XXXXXX` codes for all 18 blank spools directly via the
  Django ORM (collision-checked against all existing SKUs) — confirmed via read-only
  query afterward: 43/43 spools now have a SKU, zero duplicates.
- Added `qrcode==8.2` + `pillow==13.0.0` to `requirements.txt` (first server-side image
  generation in the project — QR was client-JS-only before). `generate_spool_label_png()`
  in `utils.py` composes a QR code + SKU + "brand color (material)" text into one PNG,
  using Pillow's bundled scalable default font (`ImageFont.load_default(size=N)`, no
  external font file needed — matters for the slim Docker image).
- `SpoolLabelView` (`/inventory/<pk>/label.png`, `?download=1` for a proper attachment
  download) and `SpoolLabelsListView` (`/inventory/labels/`) — a page listing every
  spool's label with a one-click download, plus a flagged list of any spool still
  missing an SKU (computed in the view, not via Django's `{% regroup %}`, since regroup
  only groups *consecutive* equal values and the queryset is ordered by brand/color —
  would've silently missed non-contiguous blanks).
- Un-gated the SKU/Generate/Scan/QR section in `spool_form.html` so it renders on Edit
  as well as Add (Product Library picker stays Add-only, that one's correctly
  Add-specific). Added a "Saved label" block on Edit — shown only when the spool
  already has a DB-saved SKU, server-rendered via the new label view, separate from the
  live client-side QR preview (which reflects the current *unsaved* input value and
  stays from the original Generate/Scan flow).
- Added `[SKU]` to the spool-selection option text everywhere a dropdown offers a spool
  to pick (spool assignment's primary + continuation selects, slot-split form).
  Verified by rendering a real pending-assignment print's page and grepping the output
  for `[FT-...]` tags.
- Linked the new Labels page from Inventory, next to the existing Product Library link.
