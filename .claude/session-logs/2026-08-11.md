### Dashboard Chart Clipping Fixes

- **Vertical clipping**: user reported gram amounts on the usage charts getting cropped on big-print days. Root cause: the direct value label on the chart's last point is positioned 8px *above* that point — when that point also happens to be the series max (common, since the most recent day/week is often the spike being reported), it sits exactly at the plot's top edge, and the label then rendered above the SVG's y=0 boundary and got clipped by the browser's default `overflow: hidden` on the root `<svg>`. Fixed by splitting the chart's top margin into its own constant (`_CHART_PAD_TOP = 20`, separate from the existing side/bottom `_CHART_PAD = 8`), reserving permanent headroom for the label regardless of where the data peaks. Verified with a synthetic 10,192g day on both the weekly and daily charts — label renders fully clear.
- **Horizontal clipping**: user asked proactively whether the same could happen on the right side. Explained why it can't — the label uses SVG `text-anchor="end"` anchored at a fixed x-coordinate 8px inset from the canvas edge, so it only ever grows leftward into the plot, never past the right boundary. No code change needed; confirmed via the same test screenshot.

**Files changed:** `tracker/views.py` (`_usage_chart`)

### Responsive Nav Fix (foldable / tablet widths)

- True mobile hamburger + full-width sheet (`#mobile-nav`, `md:hidden`) and the true desktop row (now `lg:`) were both left untouched.
- Verified in a real browser across 375px (mobile, unchanged), 900px (new medium tier — row hidden, Menu trigger + dropdown working, 6 links in a 2×3 grid, active-page highlighting), and 1100px (full row back, Menu trigger gone), plus the medium dropdown specifically in dark mode.
