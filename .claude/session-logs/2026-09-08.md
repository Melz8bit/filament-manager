### Feature: Material-aware default spool selection

User's example: printing black PLA was defaulting the spool-assignment dropdown to a
"Black HT-PLA" spool instead of plain "Black PLA", because the old ranking only sorted
by color distance and HT-PLA happened to be alphabetically/color-wise first.

- Found `PrintSpool` had no field storing the gcode's parsed filament type — `parsers.py`
  extracted `slot["material"]` for every file but it was discarded at every
  `PrintSpool.objects.create()` call site.
- Added `PrintSpool.slicer_material` and wired it through all 6 creation/propagation
  sites (file upload, MakerWorld queue-add, manual entry, slot split, continuation
  spool) so the material survives splits and multi-step assignment flows.
- New `rank_spools_by_material_and_color()` in `utils.py`: exact material match first,
  falls back to plain PLA if no exact match, falls back to any spool if no PLA either —
  ranks by color distance within whichever group applies. Replaced the old
  `rank_spools_by_color()` at all 3 default-selection call sites in `views.py`.

### Feature: Failed print tracking

User wanted a way to mark a confirmed print as failed and get the *unused* filament
back into inventory, with the fail point identified by layer number (read off the
printer when they cancel) or percent complete as a fallback.

- Investigated real `.gcode.3mf` structure to find out what's actually available:
  `slice_info.config` gives per-color `used_g` totals and filament `id` (maps to tool
  index `id-1`); the embedded gcode has `; CHANGE_LAYER` markers (one per layer, not
  one per transition) and real `T0`/`T1`/... tool-change commands with `M83` (relative
  extrusion) throughout the print body — confirmed against a real 4-color, 405-layer
  fixture (`uploads/prints/000ratonelectrico.gcode.3mf`).
- Chose (user confirmed via question) to parse actual per-color gcode extrusion rather
  than a naive layer-count fraction, since colors aren't used evenly across layers
  (e.g. a small logo color used only near the end).
- `estimate_remaining_by_layer()` in `parsers.py`: walks the gcode line by line,
  tracking real extrusion (E) deltas per active tool between CHANGE_LAYER markers,
  returns `{(hex, material): remaining_fraction}` plus total layer count. Verified: a
  color used only late in the print stays at 100% remaining through layer 200 while the
  bulk base color depletes proportionally; remaining fraction reaches exactly 0 at the
  final layer.
- `PrintFailedView` (new `POST /prints/<pk>/fail/`): takes `failed_layer` (preferred) or
  `failed_percent`; layer path requires the original `source_file` still be a parseable
  `.3mf`/`.gcode` — falls back to asking for percent otherwise. Credits
  `grams_used * remaining_fraction` back to each assigned spool (capped at
  `full_weight_g`), sets `PrintLog.status = "failed"` plus the layer/percent/total-layer
  fields, marks each `PrintSpool.grams_returned`.
- New model fields: `PrintLog.failed_at_layer`, `.failed_total_layers`,
  `.failed_at_percent`; `PrintSpool.grams_returned`; `PrintLog.grams_printed` property.
  Migration `0006`.
- Print History: `PrintHistoryView` queryset now includes `status="failed"` (was
  `confirmed`-only) so failed prints stay visible, with a red "Failed" badge, "Layer X
  of Y (Z%)", and "printed / total" grams.

### UI iteration on the Failed Print control (several rounds based on live screenshots)

1. First pass: inline form directly in the table's last `<td>`, toggled via a plain
   `hidden` class. Broke the table — the form's intrinsic width forced that column (and
   the whole row) to balloon horizontally and vertically.
2. Second pass: made the form `position: absolute` as a right-anchored popover. Still
   opened off the right edge of the viewport — absolute positioning inside a
   horizontally-scrollable table is fragile to reason about and not worth chasing.
3. Settled on the pattern already used elsewhere in this app for the same kind of
   problem (spool-assignment's split-slot form): a full-width `<tr colspan="6">` that
   expands in normal document flow directly below the print's row. No overflow risk by
   construction. Cancel resets the form and re-hides the row; submit is a real POST that
   redirects back to print history, where the now-failed print no longer renders the
   button at all — so it "hides" as a natural consequence of the page reload.
4. Follow-up polish from screenshots: input/button heights didn't match (inputs relied
   on browser-default padding, buttons had explicit `py-1.5` — different box models
   produced different heights) — pinned both to explicit `h-8`. Buttons then sat too
   high relative to the label-topped inputs — added an invisible spacer label
   (`invisible`, same `text-xs mb-1` as the real labels) above the button group so it
   occupies the same vertical band as the inputs, instead of relying on flex
   `items-end` alignment guesswork.
5. Widened the gap between "Calculate cost" and "Failed Print" (`ml-2` → `ml-5`).

No browser automation tool was available this session, so every round of this was
screenshot-driven by the user rather than self-verified visually — flagged that
explicitly rather than claiming a look I couldn't take.
